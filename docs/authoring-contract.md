# Контракт авторства книги 0.3.0

Автор: Igor Kramar. Исходные снимки карт для авторов создаются из текущей книги в `build/authoring/<карта>.json` (каталог не хранится в репозитории).


Работай только в своём изолированном каталоге /tmp/codex-guide-<имя>; исходники репозитория доступны для чтения. Родитель интегрирует готовые JSON.
Исходное содержимое конкретной карты: /home/ikramar/Projects/codex-aeternum/build/authoring/<section>.json.
Моды и реальные рецепты/языки/достижения: /home/ikramar/.local/share/PrismLauncher/instances/1.21.1/minecraft/mods/*.jar.
Все допустимые предметы: /home/ikramar/Projects/codex-aeternum/tools/valid_ids.txt (выгрузка реальной игры).

Для каждой назначенной карты создай <section>.json:
{
 "section":"create",
 "chapters":{"chapter_id":{"intro":["Русские абзацы"],"intro_en":["English paragraphs"]}},
 "quests":{"chapter_id/quest_id":{"text":["Русские абзацы"],"text_en":["English paragraphs"],"task_notes":{"0":{"ru":"Победить Рок-Блейза","en":"Defeat Rock Blaze"}}}},
 "additions":[{"chapter":"chapter_id","id":"new_id","title":"Название","title_en":"Title","icon":"minecraft:book","deps":["local_id"],"tasks":[{"type":"item","id":"minecraft:stone","count":16}],"optional":true,"rewards":{"xp":30,"items":[],"text":[]}}]
}
Ключ quests обязателен для КАЖДОГО существующего и нового задания в назначенной карте. Никаких заглушек или автодописанного общего шаблона.
Новые задания описываются в additions БЕЗ text, их тексты находятся в quests. Сохраняй все старые IDs. Подтверждённые ошибки целей и зависимостей исправляй через tasks_override/deps_override в записи quests; при смене смысла допустимы title/title_en и icon. Для каждого исправления передай родителю источник отдельно.
У additions отдельные title/title_en, задача task_notes может задать человеческое пояснение любой цели по индексу. Все достижения ОБЯЗАТЕЛЬНО имеют в task_notes формулировку действия на RU+EN, независимо от vanilla display. Желательно то же для dimension/biome/Ponder. Для check сохрани точные критерии ручного подтверждения.

Качество: для новичка, 3–5 содержательных абзацев, ориентир 90–160 русских слов; простая справка допускает 60–90. Разъясни назначение, подготовку и место получения, порядок действий, частую ошибку/проверку результата, что это открывает. Не превращай абзацы в одинаковые «Цель/Применение/Проверка» ярлыки. Литературный, спокойный и связный русский; без фраз «Алтарь, огонь, босс», пафоса, жевания очевидного и повторяющегося наполнителя. EN полноценный перевод, не сокращение.
Никаких выдуманных рецептов, команд или мест появления. Сверяй спорные механики с установленными JAR. JEI/Ponder — помощь и уточнение рецепта, но не замена объяснения. Наличие предмета не выдавай за автоматическую проверку работающей установки. Consume явно значит сдачу и потерю предметов. Опасные игровые устройства объясняй с нужными внутриигровыми условиями защиты.

Добавь осмысленные развилки: в карте обычно 9–15 новых заданий (несколько связных боковых цепочек с существующими входами), у маленьких карт можно 6–9. Цели различаются; не копируй 3 одинаковых setup/batch/run на всё подряд. Это обучение подсистемам, диагностика, автоматизация, снабжение и реальные экспедиции. Новые ветви optional=true, XP умеренный, не дари ключевую инфраструктуру/редкие ресурсы. ID новых заданий начинаются с guide_, ссылки на другие карты допускаются только на существующие IDs исходного снимка. Не редактируй generated/code. Не коммить. Полного build не делай.

Проверка перед сдачей: JSON читается; все назначенные старые globalId покрыты; нет пустых RU/EN; все достижения имеют человеческую task_note; все новые предметы присутствуют в valid_ids; ссылки существуют. Верни пути файлов, число заданий/новых веток и краткий список проверенных источников/обнаруженных проблем. Незавершённую часть явно укажи и продолжай до полного покрытия.

Уточнение механики прогресса: обычная item-цель НЕ consume использует исторический максимум одновременно замеченного количества ОДНОГО item ID. Разные item-цели можно показать по очереди. После обновления счётчика уже учтённую машину разрешено ставить; не нужно разбирать её снова или создавать запасной экземпляр. Количество одного предмета не суммируется за разные визиты, нужен соответствующий запас за один раз. Только consume требует все указанные ресурсы сейчас. rewards_override с полной структурой награды и icon допустимы при подтверждённой ошибке исходного задания.
