## Что это

Книга заданий в духе GTNH для большой сборки: Create и его расширения, Immersive Engineering,
Mekanism, PneumaticCraft, Refined Storage, MineColonies, Botania, Ars Nouveau, Iron’s Spellbooks,
Ad Astra, Cataclysm, Aether, Twilight Forest, Eternal Tales и десятки модов поменьше.

Каждое задание написано для человека, который открыл сборку в первый раз: зачем это нужно,
где взять, что сделать по шагам и как понять, что получилось. Русский и английский —
полноценные тексты, а не сокращённый пересказ.

## Особенности

- 📖 **Каждое задание — маленькое руководство.** Назначение, подготовка, порядок действий,
  частая ошибка и проверка результата. Спорные механики сверены с установленными модами,
  а не с чужими версиями.
- 🎯 **Цели говорят по-человечески.** Вместо `cataclysm:kill_ignis` — «Призвать и лично
  победить Игниса». Пояснения соответствуют настоящим критериям достижений: если мод
  засчитывает победу по подобранному знамени, книга так и скажет.
- 🗺️ **Карты вместо списков.** Двадцать карт собирают главы в один граф: обязательные
  предпосылки, альтернативные пути и необязательные специализации. Вход в тему —
  освоенный процесс, а не номер главы.
- 🌿 **Боковые ветки.** 204 факультативных задания учат диагностике, автоматизации,
  снабжению и экспедициям и никогда не перекрывают основной путь.
- 🏭 **Производственные проекты.** Собрать оборудование, получить партию продукции,
  подтвердить работу линии — 18 проектов, где последний шаг проверяет сам игрок.
- ⚙️ **Серверный прогресс.** Предметы, достижения, измерения, биомы и сцены Ponder
  засчитываются автоматически; сдача ресурсов и награды выдаются сервером.
- 🔎 **Подсказки и JEI.** Наведите на цель или награду: книга покажет, как получить
  предмет — рецепт и ингредиенты, с кого выпадает, в каких сундуках лежит, где добывается.
  Клик по предмету открывает рецепт или применения в JEI.
- 🧭 **Вступительный экран** объясняет, зачем нужна книга и как ей пользоваться,
  и одним нажатием ведёт к карте или к тому месту, где вы остановились.
- 🎛️ **Настройки под себя.** Порядок прохождения на выбор: строгий, как в GTNH; только
  внутри карты; свободный, где всё сделанное засчитывается сразу. Подсказки о предметах,
  уведомления и стартовый экран включаются отдельно.
- 💾 **Совместимость сохранений.** Все 907 исходных идентификаторов заданий сохранены:
  выполненное остаётся выполненным после обновления.

## Установка

1. Скачайте `codex-aeternum-<версия>.jar` со страницы [релизов](https://github.com/IgorKramar/codex-aeternum/releases/latest).
2. Положите его в папку `mods` клиента и сервера. Версии на обеих сторонах должны совпадать.
3. В игре нажмите `K` или введите `/codex`.

Без мода на сервере книга работает как локальный справочник: прогресс хранится у игрока,
награды не выдаются. Сервер хранит прогресс в `<мир>/codex/<uuid>.json`, предыдущую версию —
в `.bak`; повреждённый файл сохраняется отдельно при восстановлении из резервной копии.

## Управление

| Действие | Управление |
|---|---|
| Открыть книгу | `K` (настраивается) или `/codex`; в первый раз — вступление, потом «Обложка» возвращает к нему |
| Настроить книгу | «Настройки» на обложке: порядок прохождения, подсказки о предметах, уведомления, стартовый экран |
| Переместить карту | перетаскивание ЛКМ |
| Масштаб | колесо мыши; `Home` или «Вписать» показывает всю карту |
| Открыть задание / поставить закладку | ЛКМ / ПКМ по узлу |
| Найти задание | поиск по названию или ID предмета, `Enter` / `F3` — следующий результат |
| Перейти к предпосылке или следующему шагу | ссылка в описании |
| Введения в главы | «Обзор» |
| Рецепт / применение предмета | ЛКМ / ПКМ по предмету цели при установленном JEI |

**Как читать карту.** Сплошная связь — обязательная предпосылка (в строгом порядке). Пунктир — достаточно
одного из перечисленных путей. Ромб — необязательная ветка. Зелёный узел выполнен,
золотой доступен. Обычная предметная цель запоминает наибольший запас предмета, который
книга видела в инвентаре: показанную машину можно ставить, разбирать её не придётся.
Цели «Сдать» забирают указанные ресурсы. Ручные цели вроде «линия работает» отмечает
сам игрок по описанному критерию: блоки в инвентаре не доказывают, что фабрика построена.

## Сборка и проверки

Нужны JDK 21 и Python 3. Gradle скачивает зависимости при первой сборке.

```sh
python3 -m unittest discover -s tools/tests
python3 tools/build_book.py --check
./gradlew build
```

Артефакт появляется в `build/libs/`. Задача `build` запускает Java-регрессии модели
и сохранений; Python-проверки и соответствие сгенерированных ресурсов включены в CI.
Изолированный клиент разработки — `./gradlew runClient` (настройки, моды и миры в `build/run`).
Полный набор сторонних модов проверяйте через обычный лаунчер: не все моды поддерживают
именования методов среды разработки.

## Редактирование книги

| Файл | Назначение |
|---|---|
| `tools/guides/<карта>.json`, `tools/guidebook.py` | Полная редакция: описания заданий и введений RU/EN, пояснения целей, новые ветки `guide_*`; формат — [`docs/authoring-contract.md`](docs/authoring-contract.md) |
| `tools/c_*.py`, `tools/en_*.py` | Исходные задания, цели и награды, английские названия |
| `tools/progression.py` | Входы в главы, развилки, общий граф и координаты |
| `tools/editorial.py`, `tools/registry_corrections.py` | Исправления объяснений, целей и ссылок по реестру игры |
| `tools/curriculum.py` | Производственные проекты |
| `tools/rewards.py`, `tools/polish.py` | Награды и введения |
| `tools/book_compiler.py` | Проверка схемы, ссылок, циклов, переводов и локализация |
| `tools/build_book.py` | Загрузка исходников и выпуск ресурсов |
| `tools/hints.py` | Индекс источников предметов для подсказок (`hints.json`): рецепты, добыча, сундуки, биомы — по JAR сборки |

После правок выполните `python3 tools/build_book.py` и проверки выше. Компилятор проверяет
весь набор перед записью: ошибка в данных не изменяет JSON, а неполное руководство
останавливает сборку. `--check` ничего не записывает и завершается ошибкой при расхождении.

<details>
<summary>Формат графа и ресурсов</summary>

`deps` требует все перечисленные задания, `any_deps` — хотя бы одно. Ссылка `chapter/quest`
межглавная, `quest` — локальная. Поле `map` объединяет главы; старые книги без него
показывают каждую главу отдельно с её координатами.

Ресурсы клиента лежат в `assets/codex/book`; Gradle также помещает их в `data/codex/book`
для сервера. Книгу можно переопределить ресурспаком или датапаком; некорректная
перезагрузка не заменяет ранее загруженную книгу.

</details>

<details>
<summary>Каталоги предметов и достижений</summary>

`tools/valid_ids.txt` и `tools/valid_adv.txt` проверяют ссылки на содержимое сборки.
После изменения набора модов:

```sh
python3 tools/scan_pack.py <папка-mods> <клиентский-jar-Minecraft>
```

После смены набора модов перестройте и индекс подсказок:

```sh
python3 tools/hints.py <папка-mods> <клиентский-jar-Minecraft>
```

Точнее всего — реестр запущенной сборки. В тестовом мире с правами оператора выполните
`/neoforge dump registry minecraft:item true false` и замените `tools/valid_ids.txt`
содержимым `dumps/registry/minecraft/item.txt`. Текущий каталог получен так и содержит
19 341 предмет. Наличие ID в каталоге не доказывает доступность предмета в выживании;
источники и границы проверки описаны в [проверке содержимого](docs/content-sources.md).

</details>
